# v0.0.21 - Server dashboard

**Date:** 2026-09-03 · **Phase:** Phase 3c step 0, server log clean-up · **Harness:** 18/18 (--restart-each)
**Report:** [harness_report_v0.0.21.json](../harness_report_v0.0.21.json)

> The server's log lines now start with a short tag, the server writes a small status file once a second, and a new tool draws that file as a live, colour-coded dashboard in the terminal. No game code changed.

## Changes

**A tag on every server log line** (`serve_game.py`)
- The problem: the log was a mix of styles. Some lines started with the socket kind (`[WSS]`), some with `DEBUG_PRINT:` or `DEBUG_JOIN:`, and the words changed from line to line. You could not skim it during a match.
- Now every line starts with one short tag that says what kind of line it is:
  - `[JOIN]` someone took a seat, or was turned away (old build, or all seats taken)
  - `[LEAVE]` someone left a seat, gave it up, or did not come back in time
  - `[CONN]` a spectator socket came or went
  - `[NAME]` a name was set, or changed because it was taken
  - `[LOCK]` a class was locked in (the class name, not a number)
  - `[MATCH]` the match started or ended
  - `[ROUND]` a round started or ended, with the crowns
  - `[KILL]` who killed whom, with what, and how many lives are left
  - `[NET]` a bad packet or a network problem
  - `[STATS]` the 10-second traffic line, unchanged since v0.0.1
- The dump of every event packet (`[MSG]`) and every broadcast (`[SEND]`) moved to debug level. They still land in `debug.log`, but `server.log` is much shorter now.
- Colours appear only when the server prints to a real terminal. `journalctl`, `server.log` and `debug.log` stay plain, so nothing that reads the files has to know about colour codes.
- The file format `HH:MM:SS | LEVEL | message` did not change. The start-up banner did not change (the "Game version" line is still the marker for a new server run).

**A status file, once a second** (`serve_game.py`, `status.json`)
- The server now writes `status.json` in the repo folder every second: the version, the uptime, the match state, the round and flip count, one entry per seat (name, class, locked, connected, transport and address, alive, lives, crowns, a held seat's time left, packets per second in, queue length, dropped frames, seconds since the last packet), the spectator count, the traffic rates over the last second, and the last 40 tagged log lines.
- It is written under a temp name and then renamed, so a reader never sees a half-written file.
- Standard library only. The systemd service runs the system `python3`, not the venv, so the server must not need any new library.
- The file is in `.gitignore`.

**A live dashboard** (`tools/watch_server.py`)
- Run `./venv/bin/python tools/watch_server.py` in a terminal while people play. It reads `status.json` every second and draws a header line (state, round, flips, players, spectators, uptime), a table with one row per seat, a traffic line and a feed of the last events, colour-coded by tag.
- If the file is missing or older than 3 seconds, a red bar says the server is probably not running.
- `--plain` prints the same picture as plain text. `--once` prints one picture and exits. `--events N` shows more or fewer event lines.
- The tool never talks to the server, and the server never needs the tool. `rich` was installed into the venv for the colours (`./venv/bin/pip install rich`).

**Checked**
- The harness never reads `server.log`. It only restarts the service, finds the server by its process name and counts sockets. A smoke run and the full suite ran on the new server.

## Metrics
| Measure | before | after |
|---|---|---|
| Log line style | mixed (`[WSS]`, `DEBUG_PRINT:`, free text) | one tag per line, 10 tags |
| Every event packet in `server.log` | yes (info) | no (debug level, `debug.log` only) |
| Live view while playing | `tail -f server.log` | `tools/watch_server.py` dashboard |
| Server dependencies | standard library | standard library (unchanged) |
| Network packets | no change | no change |
| Game code | no change | no change |
