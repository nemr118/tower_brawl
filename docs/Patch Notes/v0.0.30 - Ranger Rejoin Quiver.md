# v0.0.30 - Ranger Rejoin Quiver

**Date:** 2026-09-05 · **Phase:** v0.1.0 list, bug build 3: backlog 1 and 6, the ranger arrows after a reload · **Harness:** 23/23 with --restart-each, no Minor
**Report:** [harness_report_v0.0.30.json](../harness_report_v0.0.30.json)

> A ranger who reloads the page mid-match never comes back with an empty quiver: it keeps at least 1 arrow. A save from another round no longer overwrites the fresh quiver of the round it lands in. This is the simple fallback the user chose for backlog 1 and 6; the class-kit revisit stays on the later list.

## Changes
- **`scripts/player.gd` `restore_combat_state`, the round guard.** The save that `_persist_combat_state` writes carries `round`. Before, the restore ignored it: a reload that came back after `new_round` (a hidden phone, or a reload in the replay gap whose fighter is built after the round start) restored the old round's `arrows`, `charges`, `kunai` and `bear` over the fresh quiver everyone else got at the round start. Now the ammo is restored only when `saved_round == Global.current_round`. A save from another round only keeps the movement `tick` (so the receivers never see the tick counter restart).
- **`scripts/player.gd` `restore_combat_state`, the arrow floor.** In the same round, after the restore, a ranger with `current_arrows < 1` gets `current_arrows = 1`. Why: the arrows that were stuck on the ground before the reload are not in the join snapshot (projectiles never are), so the new page cannot pick them up. Without the floor a ranger who had shot all three was disarmed until the next round. Other classes are untouched (the mage charges and the rogue kunai regenerate on their own).
- **One console line per rejoin:** `🏹 [Quiver] rejoin slot=2 round=2 saved_round=2 arrows=0->1 charges=3 kunai=4 bear=0 tick=612`. Same line in the browser console and in a headless client's stdout. After the restore `_last_persisted` is cleared, so the next movement tick writes the true state (and the current round) back to storage.
- **Harness: new scenario `ranger_rejoin` (23 total).** A protocol bot that fires nothing plus a headless ranger wanderer (`GodotClient(cls=0, keep_class=True)`). Act A: the ranger is stopped mid-round 1, the harness writes the shared headless save (`~/.local/share/godot/app_userdata/TowerBrawl/towerbrawl_combat.sav`, the same dictionary the browser keeps in `localStorage` key `towerbrawl_combat`) with `arrows: 0` for round 1 and its seat, then restarts it with `--reclaim=N`. Required: `Assigned Player ID ... (rejoined)`, a `🏹 [Quiver]` line with `saved_round=1 arrows=0->1` in the server's round, 8+ relayed spots with a 30+ px spread and at least one `spawn_projectile` from that seat in 10 s. Act B: the bot burns its stocks, round 1 ends on a kill by the ranger, `new_round` comes, and the same reload runs with a save that says `arrows: 0` for round 1: required `arrows=0->3`, plus the same move-and-shoot check. `GodotClient.quivers()` parses the line. Findings: `ranger_rejoin.no-quiver-line / wrong-save / wrong-round / arrows / stuck / no-shot / no-rejoin / no-player-left / no-round-end / no-new-round / script-error`.
- **Harness: `Bot.double_shot_ok` (backlog 15 explained).** The first run failed on `dup.movement: spawn_projectile received twice within 0.1 ms {'sender': 2, 'weapon': 'arrow'}`. Cause, now known: `player.gd` reads `attack` and `special` in the same physics frame (lines ~362 to 366); a ranger's attack and special both fire an arrow from `global_position + aim_dir * 18` in `aim_direction`, so the two `encode_projectile` packets are byte-identical, and the wanderer brain sets `attack` and `special` in one decision now and then. Two arrows, two costs, one spot: a legitimate double shot, not a relay duplicate. A scenario that plays a ranger brain sets `bot.double_shot_ok = True`; such pairs are counted in `bot.double_shots` and reported as a note (`1 same-frame double shot(s) by the ranger brain`) instead of failing. Everything else still fails on a duplicate. `reload_in_gap` keeps its knight.
- **Docs:** new sheet [[Playtest Backlog 1 — Ranger Reload Quiver]] for the browser `localStorage` path (four scenarios, eight edge cases, a `🏹 [Quiver]` table per scenario, the `keys= focus=` table so backlog 13 rides along, a verdict block).
