# v0.1.6 - Review Fixes

**Date:** 2026-09-10 · **Phase:** review fixes: the first code review of the game code, three real bugs fixed · **Harness:** 25/25 with --restart-each, no Minor
**Report:** [harness_report_v0.1.6.json](../harness_report_v0.1.6.json)

> The game code had never been reviewed. A cloud review (`/code-review ultra`) read the code that runs a real match and found 7 things. Each one was checked against the code: three are real bugs and are fixed here, one is not a bug, and three are small clean-ups.

## The review
- **What it read.** A separate clone, `~/Work/tower_brawl_review`, branch `review/core`: 13 files, 7 473 lines from master `663903c` (`serve_game.py`, `global.gd`, `player.gd`, `arena.gd`, `arena_layouts.gd`, `touch_controls.gd`, `replay_player.gd`, `history_ring.gd`, the four projectiles, `CLAUDE.md`). The branch has no history with master, so the review reads every file, not a diff. Left out: the bots, `tools/`, `character_select.gd` (the cap is 8 000 lines).
- **What it did not find.** Nothing on the server's threads and locks, the packet parsing, or the round and stock state. That is weak proof, not a clean bill: a focused read of `ws_client_thread` and the two locks is a later phase.

## Changes
- **1. A spectator's stats card was thrown away (`serve_game.py`).** The line `if assigned_id is None: continue` stood above the `client_stats` branch, so a socket with no seat never reached it, even though the branch was written for spectators (`seat` 0, name "spectator"). `status.json` `spectator_stats` was always `[]`, and `client_stats.jsonl` never got a spectator card. The branch now sits above that line. Safe: the cleanup at the end of `ws_client_thread` drops every socket's card, and `_who()` already handles no seat.
- **2. A seat taken back by the harness gate got a broken ip (`serve_game.py`).** `_demote_humans` passed `entry["addr"]`, which is already text, to `_release_seat`; `_ip()` then read two characters of it and stored `"(:'"`. `_release_seat` now takes `ip=`, and the gate passes the seat's stored `entry["ip"]`.
- **3. A name with an apostrophe was never saved (`global.gd`, `_save_player_name`).** `n.replace("'", "\'")` does nothing in GDScript (`"\'"` is just `'`), so O'Brien made broken JavaScript and `localStorage` never got the name; a name ending in `\` broke it too. The name now goes in as `JSON.stringify(n)`, a safe JS string. Not through `_storage_set`: that one deletes every `'`.
- **4. The arena's JOIN button (`arena.gd`, `_on_harness_status`).** A `harness_status` with the gate open turned "QUEUED FOR LOBBY..." back into a live "JOIN NEXT MATCH", so a second press sent a second `request_join`. It now leaves the button alone while it waits. In practice this was almost impossible to hit (only in the moment between the press and the server's answer).
- **5. Clean-up: the keyboard binds (`global.gd`).** The code that copies P1's keys to my seat ran in `assign_id`, `player_joined` and `player_left`. Only the `assign_id` copy does anything: my seat does not change in the other two. The two extra copies are gone. The review said they piled up duplicate binds; they did not (see "Checked").
- **6. Clean-up: the projectiles (`arrow.gd`, `firebolt.gd`, `kunai.gd`, `thorn.gd`).** `preload("res://scripts/player.gd").arena_w` inside `_physics_process` is now one `const PlayerScript` at the top of each file. Same behaviour (a `preload` is resolved when the script loads), easier to read.

## Found on the way (reported, not fixed)
- **The arena's JOIN button sticks on a full server** (backlog 33). `arena.gd` has no handler for `server_full`: a spectator who presses JOIN NEXT MATCH while all four seats are taken keeps a grey "QUEUED FOR LOBBY..." until the page reloads. Before v0.1.6 only a harness gate change could reset it, which never happens at a family game.
- **Review finding 7, left as is.** The projectiles wrap 10 px past the edge; `player.gd` wraps at 12 px on the sides and 16 px at the bottom. A shot only wraps in the side passages and the holes, so the 2 to 6 px never show.
- **A private key is in the public GitHub repo** (backlog 34). `key.pem` and `cert.pem`, the self-signed pair `serve_game.py` loads for the https and wss ports (`CERT_FILE`, `KEY_FILE`), are tracked since commit `671bae0`, and `tools/deploy_laptop.sh` copies them to the laptop. The fix: make a new pair on the PC, untrack both files and list them in `.gitignore` (the deploy still copies the local files); each phone accepts the new certificate once. The old key stays in the git history, so the new key is the real fix.
- **One fake line in the PC's `server.log`.** The Python test for finding 2 loaded `serve_game.py`, whose logger writes to the file: `20:07:02 | INFO | [LEAVE] P1 was moved to spectator by the harness gate` is that test, not a real event.
