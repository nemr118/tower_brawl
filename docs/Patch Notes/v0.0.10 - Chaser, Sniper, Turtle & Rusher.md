# v0.0.10 - Chaser, Sniper, Turtle & Rusher

**Date:** 2026-09-02 · **Phase:** AI bot brains (step 4 of 7) · **Harness:** 16/17
**Report:** [harness_report_v0.0.10.json](../harness_report_v0.0.10.json)

> Four combat personas for the headless bots, a fighter draw fix that let `fleet --ai` go green, and a 4-client Godot-only fleet that starts and fights on its own.

## Changes
### Client (`scripts/bot_brain.gd`)
- **Shared toolkit.** `_steer_to` (wrap-aware walking with jumps for height and when blocked), `_inbound_threat` (closest-approach test on every enemy projectile: flagged when it passes within 28 px in under 0.8 s), `_lead_point` (solves the intercept time for our projectile speed, weights the target velocity by difficulty, lifts the aim for arrow and thorn gravity), `_evade` (dash through the projectile, since dash frames are invulnerable and catch arrows, else hop), ammo awareness per class and own stuck-arrow pickups.
- **chaser** (knight by default): closes on the nearest enemy, hops up to a higher target, dashes to engage at 70–190 px on the same level, swings inside sword reach (40 px) unless the target is shielding or dashing.
- **sniper** (mage by default, the ranger's three arrows do not come back): holds a 120/170–280 px band, retreats to the platform that gains the most distance when crowded, takes high ground when settled, leads every shot, walks to its own stuck arrows when played as ranger.
- **turtle** (knight): stands its ground, shields (special) when a projectile arrives within reaction + 0.3 s or a dashing enemy is inside 110 px, then counter-attacks for 1.5 s; punishes anything inside 100 px; drifts closer only past 240 px.
- **rusher** (rogue): dashes in, dash-slashes (rogue special) inside 140 px, kunai at point blank, keeps hopping to land stomps, dashes out of inbound projectiles.
- **Void guard.** The columns beside the wrap seam (x < 55, x > 585) have no platform, so a fighter that walks in falls through the bottom wrap forever (the first sniper spent 30 s there). Steering now refuses to walk or dash into a column with no ground below, prefers the long way round the seam, and an airborne bot over a void column air-steers to the nearest platform. A `allow_void` switch is reserved for the griefer.
- Personas pick their class when no `--class` is given (`DEFAULT_CLASS`); status line gained `evades=`.

### Client (`scripts/player.gd`)
- **Cape polygon fix.** The cape quad's wave offset is clamped to ±8 px; at dash speed it reached ±17 px and self-intersected (`Invalid polygon data, triangulation failed`, ~20×/40 s from a bot, reachable by a backwards dash while mouse-aiming forward). Verified over the whole speed range: 0 self-intersecting cases.

### Tooling
- `bump_build.sh` escapes `&`, `/` and `\` in the title before the `sed` substitutions (this page's title is the test).
- Harness: `--ai` takes a comma list, one persona per Godot client round-robin; under `--ai` the fleet no longer forces `--class` so each persona plays its own class. A `--godot 4` fleet with no protocol bots starts the match by itself (the Godot lobbies run the countdown).

## Found, not fixed (outside the phase)
- **`p0_left` race, root cause.** `global.gd` copies the P1 key binds to `p<my_player_id>_*` in the `player_joined` handler whenever the id is not 1, including id 0 while the client is still a spectator. A client joining in that window logs eight `InputMap action "p0_left" doesn't exist` errors and the fleet assertion counts them: 16/17 on this build's full run (the default fleet, no brains involved), green on a re-run. Fix: guard the copy with `my_player_id >= 1`. See PASSDOWN backlog item 2.
