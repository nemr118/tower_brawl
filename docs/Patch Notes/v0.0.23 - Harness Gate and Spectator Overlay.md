# v0.0.23 - Harness Gate and Spectator Overlay

**Date:** 2026-09-03 · **Phase:** before Phase 3c: protect test runs · **Harness:** 19/19 with `--restart-each`, no Minor
**Report:** [harness_report_v0.0.23.json](../harness_report_v0.0.23.json)

> While the test harness runs, the server keeps every seat for the bots. A person who opens the game only watches, and a small ticker on the screen says which test is running and how many are done.

## The problem
The harness (`tools/chaos_bots.py`) fills the seats with bots and checks every packet. If someone opened the game on a phone in the middle of a test, they took a seat, the bot count was wrong, and the test failed for a reason that had nothing to do with the code. Nothing on the screen told them a test was running.

## The fix, piece by piece
- **The server reads `harness_state.json`** (`serve_game.py`, `_harness_tick`, once a second from `status_loop` and once at startup). The gate is closed when the file says `state` is `running` or `restarting`, the `written_at` heartbeat is under 5 s old (`HARNESS_STALE`, same number as the deck), and the harness `pid` is still alive. A hard-killed harness opens the gate after 5 s. `done`, `aborted` or no file opens it at once.
- **Humans wait.** A `request_join` with no `bot` field while the gate is closed gets a new `join_locked` packet instead of `assign_id`. The version check still runs first. Log line: `[GATE] join refused ...`.
- **Humans already seated go back to spectator.** `_demote_humans` frees every seat whose owner did not say `bot`, through the same helper as `leave_slot` (`_release_seat`, new; the old `leave_slot` body moved into it). Everyone hears `player_left`; the owner gets `join_locked` with `demoted: true`. Log line: `[LEAVE] P1 was moved to spectator by the harness gate`.
- **Bots pass.** `"bot": "protocol"` (harness bots) and any brain persona were already there. New: a plain headless Godot client (`--autojoin` without `--ai`) now sends `"bot": "headless"` (`global.gd`, `request_join`), so the `fleet` scenario and the `lag` observer still get seats. `_bot_from_join` gives it `kind: "headless"`.
- **The ticker packet.** New server-only packet `harness_status`: `active`, `state`, `scenario`, `done`, `total`, `passed`, `failed`, `minor`. Sent to everyone only when the text changes (about one per scenario) and to every new socket while the gate is closed. `status.json` carries the same dict under `harness`; the deck header says `SEATS LOCKED (harness)`.
- **The ticker on the screen** (`scripts/harness_ticker.gd`, new, built in code, no scene edits). Lobby: a dark panel with an amber border in the JOIN MATCH spot, three lines: `TESTS RUNNING - JOIN IS LOCKED`, `Scenario: <name>`, `Tests done: X / Y`. JOIN MATCH and LOCK IN hide while locked (`_update_roster` in `character_select.gd`). Arena: one line under the top bar on the right, `TEST LOCK | <name> | Tests done: X / Y`; the spectator's JOIN NEXT MATCH button hides and comes back when the run ends (`arena.gd`, `_on_harness_status`). A demoted fighter loses its body and sees `THE TESTS TOOK YOUR SEAT. WATCH UNTIL THEY FINISH.`
- **Client plumbing** (`global.gd`): `harness_info` dictionary, signals `net_harness_status(info)` and `net_join_locked(demoted, old_id)`. `join_locked` is handled like `server_full` for a pending rejoin.
- **Harness** (`tools/chaos_bots.py`): `harness_status` and `join_locked` in the schema table (else `schema.unknown-type`). `Bot.join(bot=None)` sends no bot field, to play a human. New scenario `harness_gate` (19 total): the human sees the ticker with `scenario == "harness_gate"`, gets `join_locked` and no `assign_id`, a protocol bot and a `"headless"` client get seats, the human still hears `player_joined`.

## Checked
- `check_scripts.gd`: 15 scripts compile.
- `harness_gate` alone with `--restart-each`: PASS in 3.7 s.
- Demotion, by hand: a fake human took seat 1, then `--scenario smoke` ran without a restart. Within a second the human got `player_left` (id 1), `join_locked` (`demoted: true`, `scenario: "smoke"`), `harness_status`; seat 1 went to a bot; at the end `harness_status` with `active: false`. Server log shows the `[GATE]` open and close lines.
- Full suite `--restart-each`: 19/19, no Minor. Report in `harness_report_v0.0.23.json`.
