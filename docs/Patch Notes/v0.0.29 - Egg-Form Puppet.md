# v0.0.29 - Egg-Form Puppet

**Date:** 2026-09-05 · **Phase:** v0.1.0 list, bug build 2: backlog 10, the egg-form puppet · **Harness:** 22/22 with --restart-each, no Minor
**Report:** [harness_report_v0.0.29.json](../harness_report_v0.0.29.json)

> A puppet (another player's fighter on your screen) can no longer run the egg branch of the game loop. Before, a puppet drawn as an egg fell with your screen's gravity and sent movement packets under your own seat number. Also in this build: a new playtest sheet for the open PC keyboard part of backlog 13, and the filled-in family sheet [[Playtest v0.0.26]] is restored (the v0.0.28 commit had cut it to its result line).

## Changes
- **`scripts/player.gd` `_physics_process`, the order of the branches.** Before: `if is_egg:` (egg timer, friction, gravity, `move_and_slide`, `_check_screen_wrap`, `_sync_network_state`, return), then the shared timers (`spawn_invuln_timer`, `bubble_timer`, `shield_timer`, `dash_timer`), then `if not is_local_player:` (the puppet branch, return), then the local controls. Now: the shared timers, the puppet branch, `if is_egg:`, the local controls. A puppet never reaches the egg branch, so it never runs local gravity and never calls `_sync_network_state`. Its `is_egg` comes from the sender's `sync_pos` flag bit 16 through `_apply_state`, the same way as `dash`, `shield` and `bear`. The puppet branch still ticks `bubble_timer`, which it needs for its late bubble safety (`bubble_timer <= -0.5`).
- **Why the old order was wrong.** A head stomp on a shielding druid puppet calls `take_hit` on that puppet node, which sets `is_egg = true` on the stomper's screen. The egg branch then ran on the puppet: gravity and `move_and_slide` moved it with local physics, and `_sync_network_state` sent `sync_pos` from that node over the stomper's socket, so the server relayed a second movement stream under the stomper's seat. Other screens saw the stomper's fighter jump between two spots for the 3 s egg time.
- **Ticking the shared timers during a local egg is harmless.** `take_hit` returns early for a dashing, bubbled or invulnerable fighter, so `dash_timer`, `bubble_timer` and `spawn_invuln_timer` are already zero when an egg starts; `shield_timer` running out sets `is_shielding = false`, which `take_hit` already did.
- **Found while reading, not fixed (new backlog 16):** the stomp-egg has no author over the network. `_check_head_stomp` runs only in the local branch, so a stomp is only seen on the stomper's client, and `take_hit` on a shielding druid returns before sending any packet. The druid's own client never enters egg form. Before this build the egg was a local illusion on the stomper's screen; after it the puppet's egg flag follows the druid's own packets, which never say egg, so the egg form does not show anywhere in a networked match. Fixing that needs a hit report packet (an observer tells the server, the victim's client runs `take_hit` on itself), which is a design call, not part of this bug build.
- **Docs:** new sheet [[Playtest Backlog 13 — PC Reload Input Probe]] for the open PC part of backlog 13 (reload during a replay, mid-round, the control, seven edge cases, `keys=` and `focus=` tables, a verdict block). [[Playtest v0.0.26]] restored to its 172 lines from commit 59bc2ca with the v0.0.28 result line kept.
