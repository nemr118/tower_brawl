# v0.1.2 - Cut 1

**Date:** 2026-09-08 · **Phase:** v0.1.2 build 2: cut 1 proper, the self-respawn safety net, a web client on the PC · **Harness:** 25/25 with --restart-each, no Minor
**Report:** [harness_report_v0.1.2.json](../harness_report_v0.1.2.json) · the sheet: [[Playtest — Master Validation Suite v0.1]] §5 · the decision: [[release-v0.1.0]] §5

> The two phones' first match (v0.1.0, 2026-09-07) had two rough spots outside play: the first replay of the match hitched (89 ms on the S25 Ultra, 52 ms on the Pixel) and the S25's lobby had 21 to 35 ms script frames with two frames over 50 ms at the locks. This build reads the cards again, names both causes, and moves the work into the scene loads. It also carries the client self-respawn safety net from backlog 27, a probe in the replay line, and a way to run a real web client on the PC.

## What the cards said (a second reading)
- **The lobby's steady state on the S25 was fine:** 4 to 6 ms script frames at 60 fps for two minutes. The 21 to 35 ms were three events: the Pixel joining (23:32:23, 20.9 ms), the two locks (23:32:28, 22.0 ms, two frames over 50 ms) and the return to the lobby after the match (23:36:27, 34.6 ms, a scene load).
- **The replay card (23:33:07) showed the physics number at 16 ms as well.** That is the catch-up, not the cause: after an 89 ms frame Godot runs five physics ticks in one frame and the monitor keeps their sum. The probe below says the freeze tick's script work is under a millisecond.
- **The first "knocked out" banner** (23:32:43, the first kill) lifted both phones' script time in that card (14 to 17 ms, from 7 to 9): the same first-draw cost as the replay, smaller.

## Changes
- **The lobby icons** (`assets/icons/*.jpg.import`, `scripts/character_select.gd`). The cause: `_update_player_card()` called `load()` on an icon for every card on every roster change (a join, a name, a lock, the reveal). The icons were 1024 x 1024 lossless textures (about 0.8 MB each in the .pck, 4 MB on the GPU) drawn at 30 px. An icon no card held yet (the "locked" one at the first lock, the other player's class at the reveal) was read out of the .pck, decoded and pushed to the GPU on that frame. The fix: `process/size_limit=256` on the twelve big icons (one text line in each `.import`, reimported), so they are 256 x 256 now; and the lobby keeps every icon it can show in a table loaded with the script (`ICON_TEX`, `_tex()`, `_set_tex()`) and swaps a card's texture only when it changes. The `.pck` went from 21.9 MB to 12.9 MB, which is what a phone downloads once per build.
- **The font warm-up** (`scripts/font_warmup.gd`, new; added by `arena.gd` and `character_select.gd` at load). Godot draws a glyph the first time it is needed: it rasterizes it (at the screen's oversampling, about 5x on the S25's 3123 px width), puts it in an atlas and uploads the atlas. Every (font size, outline size) pair has its own atlas. The replay overlay uses three pairs nothing else had drawn (18/3, 16/3, 12/3) and the kill banner uses 20/4 with lower-case names. The warm-up draws the printable ASCII range once, off-screen, for those pairs, prints `🔤 [FontWarm] pairs=4 ms=14` and frees itself. On the PC web build: 30 ms for eight lobby pairs and 14 ms for five arena pairs the first time, 0.2 ms the next match (the atlas lives as long as the page); shipped with four pairs each.
- **The ghost pool** (`scripts/replay_player.gd`). The ghost fighters are made hidden at the arena's load (`prepare_ghosts()`), not inside the freeze tick of the first replay; `stop()` hides ghosts and ghost projectiles instead of freeing them, so the next replay reuses them. A ghost whose seat changed class mid-match is re-classed on reuse.
- **A probe in the replay line** (`replay_player.gd`, `arena.gd`, `serve_game.py`): `📼 [Replay] ... start_ms= tick_ms= first_ms=` = `start()` itself, the whole freeze tick's script cost, the slowest of the first three drawn frames. The same three ride in the replay card, and the server writes one `{"kind":"replay", ...}` record per played replay into `client_stats.jsonl`, so a phone's numbers can be read the next day (`grep '"kind":"replay"'`, or `stats_table.py --events`).
- **The self-respawn safety net** (backlog 27's other half; `scripts/arena.gd` `SELF_RESPAWN_S = 1.0`, `scripts/player.gd` `death_report_msec`). When my fighter reports its own death and no `player_died` comes back within a second, it respawns on its own and prints `🩹 [SelfRespawn] slot= round= waited_ms= stock=`. The echo (`_on_net_player_died`) and `respawn()` clear the mark. In that case the server thinks the fighter is alive (the report was folded into an older death, or lost), so both sides agree again. Zero lines in the PC match below, as it should be.
- **A real web client on the PC** (`tools/webbot.sh`, `web/shell.html`, `scripts/global.gd`, `serve_game.py`). `?arg=--autojoin&arg=--ai=chaser` on the page URL hands the headless flags to the game; Chromium headless (SwiftShader, software GL) plays with a bot brain and its console goes to `.bots/web<N>.log`. The server's `/` redirect keeps the query string now. `--no-warm` skips the warm-up and the pool (the A/B knob).

## The PC measurement (web build in Chromium, 1280 x 720, two web bots in one four-player match with two headless bots)
| | WebWarm (P2, warm-up on) | WebCold (P1, `--no-warm`) |
|---|---|---|
| cards / replays | 44 / 7 | 44 / 7 |
| script frame in play (`proc`) | 7 to 8 ms (SwiftShader draws) | 7 to 8 ms |
| hitches after the arena load | 0 | 0 |
| `start_ms` / `tick_ms` / `first_ms`, every replay | 0.1 to 0.2 / 0.4 / 17 | 0.1 to 0.3 / 0.4 to 0.6 / 17 |
| `🔤 [FontWarm]` | lobby 30 ms (8 pairs), arena 14 ms (5 pairs); 0.2 ms the next match | (none) |

Read: the script side of a replay start is under a millisecond even cold, so the phone's 89 ms was the first draw (glyphs at 5x oversampling, the atlas upload, the ghosts' first draw), which is what the warm-up and the pool move to the load. The hitch itself does not show on the PC (2x oversampling, a fast CPU and GPU): the phones are the proof, sheet section 5.

## Harness
- **Full suite:** 25/25 with `--restart-each`, no Minor, seed 42, on the v0.1.2 build (report written 17:14). The `replay` and `tape` scenarios read the `📼 [Replay]` line by its fields, so the three new fields at its end change nothing for them. The suite restarts the PC service before every scenario, so a `systemctl --user restart towerbrawl` by hand during a run collides with it (done once here, during scenario 1, which still passed).
