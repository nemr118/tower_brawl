# v0.0.36 - Relay Packet Coalescing

**Date:** 2026-09-05 · **Phase:** optimisation Step C, build 3: the relay sends movement as one `sync_bundle` per client every 50 ms · **Harness:** 24/24 with `--restart-each`, no Minor (the new `bundle` scenario included)
**Report:** [harness_report_v0.0.36.json](../harness_report_v0.0.36.json) · design: [[optimisation_step_c_bundle]] · human check: section 5 of [[Playtest — Master Validation Suite]]

> The server no longer forwards every fighter's `sync_pos` the moment it arrives. It holds them for up to 50 ms and sends ONE binary `sync_bundle` frame per client. Packets into a screen fell from about 38 to about 17 a second (-55 %); the bytes barely moved, because the packet count was the cost (Profile 3 of [[optimisation_step_b_profiles]]). Three files changed: `serve_game.py`, `scripts/global.gd`, `tools/chaos_bots.py`. The game rules, the client's send path and the other packets are unchanged.

## Changes
- **`serve_game.py`.** New `RELAY_BUNDLE_MS = 50` (0 = the old way, no client rebuild needed), `BIN_SYNC_BUNDLE = 3`, `BIN_BUNDLE_ENTRY = 10`, `BIN_BUNDLE_MAX = 25`. New `MovementBatcher` (thread `batcher`): the reader threads hand a stamped type 1 packet to `batcher.add(slot, sock, payload[1:])` instead of `broadcast`; every 50 ms it flushes one frame per kind of recipient. A recipient never gets an entry from its own slot or from its own socket (a fighter that pressed leave is a spectator by the flush and must still not hear itself; the first suite run failed `simultaneous_leave` on that, finding `oracle.bundle-own-echo`, fixed before the clean run). Bundles are queued as movement, so backpressure drops them first. `spawn_projectile` is still relayed at once. The `[STATS 10s]` line ends with `bundles=18.7/s x2.7` (bundles a second, mean entries).
- **`scripts/global.gd`.** `BIN_SYNC_BUNDLE`, `BIN_BUNDLE_ENTRY`. `_handle_net_binary` accepts a frame of `2 + 10 n` bytes and emits `net_player_state_received` once per entry through the new `_emit_sync_entry(pkt, base)` (also used for a plain `sync_pos`, so type 1 still works). NetStats counts the frame under `sync_bundle` (2 B) and each entry under `sync_pos` (10 B). `player.gd` unchanged.
- **`tools/chaos_bots.py`.** `decode_bundle` flattens a frame into `sync_pos` dicts that run through the same schema, duplicate, oracle and reaction path, so every scenario that counts relayed movement works unchanged. New findings `oracle.bundle-size` and `oracle.bundle-own-echo`. `fuzz` sends a type 3 frame from a client: dropped, not relayed. New 24th scenario `bundle` (3 bots at 20 Hz for 10 s and a watching socket): 16 to 22 bundles a second, about 2 entries per fighter bundle and 3 for the watcher, no loose `sync_pos`, relay delay p95 under 70 ms. `fleet` notes print `in N pkt/s (B sync_bundle, S sync_pos)`; the METRICS line counts a bundle as one packet.
- **Docs.** [[optimisation_step_c_bundle]] (the design), section 5 of the master sheet (the phone feel check), [[Commands]] (24 scenarios, the new `in:` fields), cut 3 marked done on the Step B page.

## Harness
- **Full suite:** 24/24 with `--restart-each`, no Minor. `bundle`: 20.0 bundles/s x 2.00 entries on every fighter, x 3.00 on the watcher, relay delay mean 24 to 49 ms, p95 49 ms, max 51 ms (the bots' 50 ms ticks lock phase with the server's windows, so each run sits at one point of the 0 to 50 ms range).
- **Fleet before and after** (`--godot 4 --ai chaser,sniper,turtle,rusher --duration 90 --latency-ms 120 --jitter-ms 40`): the table. The before run (v0.0.35) failed its gameplay verdict on `fleet.bot-fall-loop` (Godot4 rusher, 4 bottom wraps without landing), a brain finding in code this build does not touch; its telemetry is still the baseline. The after run passed.

## Metrics

|---|---|---|

| Outbound from a client | unchanged | unchanged |
| Files changed | — | `serve_game.py` (+110), `scripts/global.gd` (+40, -20), `tools/chaos_bots.py` (+130) |

Bundles a second are about 15, not 20: idle suppression, deaths and the round gaps leave some 50 ms windows empty. The honest cost is the `extrap` row: the puppets more often run a few frames past their newest sample before the next bundle lands, which the jitter gate does not see and a person might. That is what section 5 of the master sheet asks a phone to judge. If it feels late, `RELAY_BUNDLE_MS = 0` in `serve_game.py` and a service restart turn it off without a client build.
