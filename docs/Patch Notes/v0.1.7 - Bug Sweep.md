# v0.1.7 - Bug Sweep

**Date:** 2026-09-10 · **Phase:** bug sweep: backlog 31 to 34, 4, 5 and 20 in one pass, and the docs cleaned up for the design session · **Harness:** 25/25 with --restart-each, no Minor
**Report:** [harness_report_v0.1.7.json](../harness_report_v0.1.7.json)

> The game plays well, so this build only clears bugs and small open items. Down + jump drops through a ledge every time. Bots get a seat after `tbbot clear`. JOIN on a full server says so. The TLS key is out of the repo, the logs keep one old file, and the backlog is split into "watching" and "decisions".

## Changes
- **1. Down + jump jumped instead of dropping (backlog 31, `player.gd`).** Down starts a duck, and the duck changes the collision shape. For 2 frames after that `is_on_floor()` is false, and for up to 3 frames around frame 7 to 9 `_on_ledge()` is false while the duck settles. A jump in those frames was a plain jump. Now the drop counts the duck grace as ground, and `_ledge_grace` remembers the ledge for `LEDGE_GRACE_S` 0.1 s. A `dropped_now` flag stops the jump trap from printing a false `vel=(x, 60.0)` line on every drop. `bot_brain.gd` is unchanged (`DROP_STEADY_FRAMES` stays).
- **2. A bot added right after `tbbot clear` never got a seat (backlog 32, `global.gd`).** The server holds a leaving seat for 8 s and sends `spectator_state` only on connect. The bot asked once, heard `server_full`, and waited for ever. Now `_autojoin_retry_timer` (built like `_reconnect_timer`) asks again: `🤖 [Global] --autojoin: all 4 seats are taken, asking again in 2 s (try N)`, every 2 s for 10 tries, then every 10 s. It stops on `assign_id`, `version_error`, `join_locked` and a disconnect.
- **3. JOIN on a full server (backlog 33, `global.gd`, `arena.gd`, `character_select.gd`).** New signals `net_server_full` and `net_disconnected`. In the arena, "QUEUED FOR LOBBY..." becomes a grey "ALL SEATS TAKEN" for 2 s (`create_timer`), then a live "JOIN NEXT MATCH". The lobby does the same on "JOIN MATCH". A socket drop gives a waiting arena button back. A press with no socket does nothing (no request can go out).
- **4. The arena's JOIN button handlers never found the button (found on the way, `arena.gd`).** Since v0.1.3 the button sits on the HUD layer (`$HUD.add_child`), but all seven handlers asked for `get_node_or_null("JoinBtn")` at the scene root and got nothing. So the button never greyed, the test gate never hid it, `version_error` never marked it, and it never came back after SPECTATE. They now ask for `HUD/JoinBtn`. This also means backlog 33 as written in v0.1.6 was read from the code: the real button never showed "QUEUED FOR LOBBY...", and the v0.1.6 fix to it had no effect until now.
- **5. The TLS key (backlog 34).** A new self-signed pair on the PC: RSA 2048, CN 192.168.4.21, SAN 192.168.4.21 and 192.168.4.29, valid to 2028-12-14. `git rm --cached cert.pem key.pem`, and both are in `.gitignore`. `tools/deploy_laptop.sh` still copies the local files. The old key stays in the git history, so the new key is the real fix.
- **6. Logs (backlog 4, `serve_game.py`).** `server.log` and `debug.log` use `RotatingFileHandler` (`LOG_MAX_BYTES` 50 MB, `backupCount=1`): one `.1` each, on the PC and the laptop. The laptop's `/etc/logrotate.d/towerbrawl` (5 kept, compressed) had never rotated: at each daily run both files were under 50 MB. `tools/deploy_laptop.sh` now deletes it. `tools/pull_laptop_logs.sh` also pulls `server.log.1`. `tools/chaos_bots.py` reads the server log from the start again if it shrank below the scenario's mark. `.gitignore` gains `*.log.1`.
- **7. One default class (backlog 5, `global.gd`).** `player_configs` gave P2 a knight, P3 a mage and P4 a rogue that nobody picked. Every seat now starts as `DEFAULT_CLASS` (Ranger); the real class still comes from `lock_in` or `locked_players`.
- **8. The jump trap's own lines (backlog 20, `player.gd`).** None of the 45 "jumped last frame but is back on the floor already" lines in the laptop bot logs (2026-09-07 to 09-10) has vy 60. The sweep found one clear cause: a ranger's jump + special aimed up in the same frame. The shot's push-back (`-aim * 310 + UP * 160`) replaces the jump's upward speed, so the fighter never leaves the floor, and the trap called it a lock. The trap now only counts a jump that still goes up at `move_and_slide` (`_jump_fired_frame`, a physics frame number). A jump + dash (sideways or down-right), a knight's jump + shield and a mage's jump + blink print nothing, before or after. So the lines with ±470 to 518 px/s are still not explained. No line shows a real W lock. Backlog 20 moves to "watching": the next real line matters.
- **Tools.** `tools/nav_probe.gd --drop-test` is now a sweep, 135 cases (see "Checked"). It presses keys from the SceneTree's `_process`, between physics frames, like a real key. New `tools/join_full_probe.gd`: `--no-net` sends the signals into both scenes; `--live` presses the real button on a full server. `player.gd` counts its trap lines in `jump_trap_count` so a probe can fail on one.
- **Docs.** Closed 4, 5, 11, 12, 14, 31, 32, 33, 34 ([[closed]]). PASSDOWN has one "watching" line (3, 13, 20, 25, 26) and a "decisions" list (16, 17, 18, 21, 28, 29, tower build 2, a v0.2.0 tag). The master sheet moved to `archive/playtests/` unchanged; [[Playtest v0.1.7]] is the short sheet.

## Found on the way (reported, not fixed)
- **`tblog` on the laptop is `tail -f`** (`~/.bashrc`: `alias tblog="tail -f $HOME/tower_brawl/server.log"`). After a roll-over it keeps reading `server.log.1`. `tail -F` follows the new file. This matters only after 50 MB (weeks of play).
- **A full server now logs a retry.** Each retry of a fifth bot writes `[JOIN] rejected ... all 4 seats are taken` (WARNING) to `server.log`: every 2 s, then every 10 s. `tbbot` never starts a fifth bot, so this only shows in the seconds after a clear.
- **The drop sweep prints one `🏃 [Speed]` line.** It is the probe: it resets the dash cooldown between cases, so the speed check thinks a dash ended long ago.
