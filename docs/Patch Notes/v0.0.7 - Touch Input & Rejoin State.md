# v0.0.7 - Touch Input & Rejoin State

**Date:** 2026-09-02 · **Phase:** Playtest fixes, phone pass · **Harness:** 16/17
**Report:** [harness_report_v0.0.7.json](../harness_report_v0.0.7.json) · **Playtest:** [[Playtest v0.0.5]]

> The two bugs the phone found on v0.0.6: joystick touches fired arrows, and a reload mid-match came back with a full quiver.

## Changes
- **Touch input bleed.** Godot emulates a mouse click from every touch and the input map binds mouse button 1 to attack (2 to special), so every joystick touch was a left click. Touch devices now strip the mouse-button bindings from all player actions (`Global.strip_mouse_binds()`, on reveal of the touch controls and on slot assignment). The touch controller marks the screen touch/drag events it handles as consumed.
- **Rejoin keeps combat state.** `assign_id` carries `rejoined=true` when a socket resumes its own seat in a running match (page reload inside the 8 s grace, or hot reclaim). `player.gd` persists arrows / charges / kunai / bear form to storage whenever they change; `arena.gd` restores them for the local fighter on a rejoin. Stocks now always come from the server (`Global.server_stocks` from snapshots, `player_died`, `new_round`), so a rejoining client shows the real count instead of a fresh 3.
- Harness: `reload_mid_match` asserts the `rejoined` flag; every fresh join asserts it is absent.
