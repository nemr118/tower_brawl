# v0.0.20 - Bubble faces and steady spins

**Date:** 2026-09-03 · **Phase:** Phase 3b step 5, playtest fixes · **Harness:** 18/18 (--restart-each)
**Report:** [harness_report_v0.0.20.json](../harness_report_v0.0.20.json)

> The third small fix build after the playtest: a fighter inside the spawn bubble can look around again, and a round start no longer lands anyone on a platform that is still turning.

## Changes

**The fighter looks around inside the bubble** (`player.gd`)
- The problem: in the v0.0.19 playtest a fighter inside the bubble stood like a statue. The aim line and the face were stuck. You could not tell which way anyone was looking. This happened in both bubbles: the still one at round start and the floating one after a death.
- Why: the bubble code returned early, before the block of code that reads the mouse or the stick and turns the fighter.
- Now that block is its own little function, `_update_aim`. The normal code calls it as before. Both bubble branches call it too. So the fighter turns and aims while the bubble is up. On a PC the mouse steers the look. On a phone, or for a bot, the stick does.
- The aim goes out in the movement packets, so the other screens turn the puppet as well. A change of aim alone is enough to send a packet, even when the fighter stands still.
- Nothing else about the bubble changed. It still pops on the first key press, on the ground, or when the timer runs out.

**A round start finishes the arena spin first** (`arena.gd`)
- The problem: the arena spin takes 2.5 seconds. The next round comes 2.6 seconds after the last kill. So a round could start while the platforms were still turning. The game read the live angle and rounded it to the nearest half turn, so the answer switched halfway through the spin. Two screens could even disagree if the round started right at that moment. Fighters were then put on platforms that had not arrived yet.
- Now the game remembers the running spin in `spin_tween`. When a round starts, `_finish_spin_now` stops the spin and jumps the platforms to where the spin was going. The platform spots are then read from the server's flip count (`Global.arena_flips`), not from the live angle. Every screen has the same count, so every screen picks the same spots.
- The old 2.5-second timer that ends a spin now checks that it still owns the spin, so a spin finished early by a round start cannot switch off a newer spin.

**Checked and left as it was**
- The spawn spots are worked out only inside the round start code, which runs when the server sends `new_round` or when the match begins. No other code path picks spots.
