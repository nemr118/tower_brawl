# v0.0.37 - Client Stats Reporting

**Date:** 2026-09-07 · **Phase:** playtest tooling: every device mails its NetStats card to the server; the v0.1.0 release candidate · **Harness:** 24/24 with `--restart-each`, no Minor
**Report:** [harness_report_v0.0.37.json](../harness_report_v0.0.37.json) · sheet: [[Playtest — Master Validation Suite]] · release: [[release-v0.1.0]]

> Until now the phone's frame numbers only existed in its browser console, which needs a USB cable and Chromium on the PC, and the iPad has no such path at all. Now every client (phone, tablet, PC, headless bot, spectator too) sends the same numbers to the server every 5 s as a small JSON card, `client_stats`. The server keeps the newest card per socket for `status.json` (the deck's new Screen column) and appends every card, plus a marker at every match and round start and end, to `client_stats.jsonl`. A new tool, `tools/stats_table.py`, turns a match or a clock window into one row per device. The playtest sheet now asks for clock times only. No game rule, packet format or relay path changed; the card is never relayed.

## Changes
- **`scripts/global.gd`.** `_report_net_stats` ends with `_send_client_stats(stats)`: the printed numbers, rounded, as `{"type": "client_stats", "schema": 1, "v", "scene", "spec", "up", "rtt", "in_pps", "in_bps", "out_pps", "out_bps", "bundles", "sync", "pj": {...}, "fps": {...}, "keys", "focus", "win", "dev": {...}}`. `dev` is filled once in `_ready` by `_device_info()`: `OS.get_name()`, `OS.get_model_name()`, the screen refresh rate, the screen size, the renderer, a `headless` flag and on web the first 120 characters of `navigator.userAgent`. `client_stats_enabled = true` turns it off. 543 B per card, one card per 5 s per client (about 110 B/s, under 1 % of the movement traffic). Sent after the counters reset, so the card counts in the next window's `out:` list as `client_stats=1(543B)`.
- **`serve_game.py`.** New `client_stats` branch next to `bot_status`: cap `CLIENT_STATS_MAX_BYTES = 1024`, stamps `seat` (0 for a spectator), `name`, `addr`, `link`, `state`, `round`, keeps the card in `client_stats[id(sock)]` (popped on disconnect) and appends it to `CLIENT_STATS_FILE` (`client_stats.jsonl`) through `_stats_log`, which adds `t` (epoch) and `clock` (HH:MM:SS) and rotates the file to `.1` at 10 MB. Markers from the same helper: `{"kind": "server", "event": "start"}` at boot, `match start` (players and names), `round start`, `round over` (winner, crowns, `match_over`), `match end` (reason, winner, rounds; the idle reset too). `status.json`: each seat gets `"stats"` (its newest card) and the file gets `"spectator_stats"`. Never relayed, never sent to a player.
- **`tools/stats_table.py`** (new). `--list` the matches in the file, `--match N` or `--last N` one table per match, `--from HH:MM --to HH:MM` a clock window, `--by-round` one table per round, `--scene Arena` to keep only arena cards, `--devices` who reported (model, OS, screen rate, browser), `--raw` the cards. One row per device: cards, draw, phys, worst, hitches, proc mean/max, phys_cpu mean/max, rtt, IN pkt/s, bundles per 5 s, jitter, p95, snaps, stall %, extrap %, keys, focus. The first card after a scene change (the load spike) is skipped unless `--keep-load`.
- **`tools/watch_server.py`.** Seat column **Screen**: `60fps 1.2ms` (draw a second and `proc` ms from the seat's card), shown once a card has arrived, in the live and the plain view.
- **`.gitignore`.** `client_stats.jsonl*`.
- **Docs.** The master sheet asks for clock times instead of pasted lines: a match log in section 0.1, section 1.3 as one situations table, section 1.1 (the USB console) marked optional, sections 3, 4, 5.3 and 6.5 point at the tool. [[release-v0.1.0]] names v0.0.37 as the release candidate. [[Commands]] has the tool.

## Harness
- **Full suite:** 24/24 with `--restart-each`, no Minor (0 finding kinds, 0 warning kinds on every scenario). The cards from the headless fleet clients landed in `client_stats.jsonl` during the run and changed nothing: the card is client-to-server only, so the oracle never sees it, and the `out:` regexes match their own type names.
- **Live check before the bump (v0.0.36 server code, headless clients):** one chaser bot for 18 s: 3 cards in the file, each 543 to 544 B, the tool prints its row. Two brains (chaser, rusher) for 45 s: the `match start`, `round start`, `round over` and `match end` (idle reset) markers landed in order, `--list` shows `match 1: 11:09:47 to 11:10:35 rounds=1`, `--last 1 --scene Arena` prints both bots with `IN pkt/s` 14 to 19 and `bundles/5s` 66 to 86. No server error since the restart.
