# v0.0.9 - Bot Brain Plumbing & Wanderer

**Date:** 2026-09-02 · **Phase:** AI bot brains (steps 1–3 of 7) · **Harness:** 17/17
**Report:** [harness_report_v0.0.9.json](../harness_report_v0.0.9.json)

> A headless client started with `--ai=<persona>` now plays by itself: `scripts/bot_brain.gd` reads the scene tree and presses the same input actions a human does, and the first persona (`wanderer`) is verified end to end.

## Changes
### Client
- **`scripts/bot_brain.gd` (new).** Attached by `arena.gd` to the local fighter when `Global.ai_persona` is set. `player.gd` is untouched: the brain perceives through the `players` / `projectiles` groups, the arena platforms (rect shapes read from the collision shapes, so arena flips are followed) and the powerup, and acts with `Input.action_press/release` on `p<N>_left … p<N>_special`. Aim goes through a synthetic `InputEventMouseMotion` placed at the inverse viewport mapping of the world aim point, so the unchanged mouse-aim branch reads it like a real mouse (`Input.use_accumulated_input` is switched off because the headless display server never flushes the buffer).
- **Frame ordering.** `process_physics_priority = -10` puts the brain before the fighter in the same physics frame, so `is_action_just_pressed` sees every tap exactly once; taps are released on the next frame, jumps are held for a decided 50–300 ms for variable height.
- **Human-likeness knobs.** Decisions run at 10 Hz and wait in a queue for a reaction delay (250 ms at difficulty 0 down to 100 ms at difficulty 1, ±30 % jitter), aim carries gaussian error (15° down to 2.5°), and everything random comes from one seeded RNG (`--ai-seed=N`, 0 = random, the seed is printed).
- **Wanderer persona.** Picks a platform or a random x every 0.8–2.5 s (shortest way across the wrap seam), pauses 0.3–1.2 s a quarter of the time (exercises idle suppression), jumps for higher targets, when stuck against a ledge, or at random, dashes now and then, aims at the nearest enemy and attacks when within 280 px. The other five personas fall back to wanderer until built.
- **Self-check.** A `🧠 [Bot …]` status line every 5 s reports position, action counts, the queue and the measured aim error (last frame's request vs the fighter's `aim_direction`); a warning fires if the synthetic mouse stops reaching `player.gd`.
- `global.gd`: new flags `--ai=<persona>`, `--ai-seed=N`, `--ai-difficulty=0..1`, `--latency-ms=N` (every outgoing packet is delayed by a SceneTree timer, order preserved, so a bot on the server machine can be given a real RTT). An unknown persona is rejected with an error at start.

### Harness
- `--ai <persona>` on the fleet scenario passes `--ai=` and a per-client `--ai-seed` (derived from `--seed`) to every Godot client. Assertions unchanged for now (step 6 adds the fought/rounds notes).

## Found, not fixed (outside the phase)
- **`player.gd` cape polygon self-intersects while dashing against the facing direction** (`_draw`, the `cape_pts` quad: `cape_wave = sin(...)*3 - velocity.x*0.03` reaches ±16–20 px at dash speed 550 and flips the quad). Godot logs `ERROR: Invalid polygon data, triangulation failed.` about 20 times per 40 s with a wanderer, and the fleet scenario counts it as a script error, so **`fleet --ai <persona>` is red until this is fixed**. Reachable by a human (dash with the movement keys while mouse-aiming the other way); on the web build it only spams the console. Fix candidate: clamp `cape_wave` to about ±8.
- **`bump_build.sh` and `&` in titles.** The `{TITLE}` / `Next:` substitutions use `sed` with the title in the replacement, where `&` means "the match". This page and the v0.0.8 footer were repaired by hand; avoid `&` in titles until the script escapes it (escape `&`, `/` and `\` in `$TITLE` before it goes into the `sed` replacement).
