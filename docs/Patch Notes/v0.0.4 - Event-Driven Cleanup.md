# v0.0.4 - Event-Driven Cleanup

**Date:** 2026-09-02 · **Phase:** Phase 1 · **Harness:** 9/9 at build time; the Step-2 harness (fleet, fuzz, lag, slow_reader, stop_pinging, soak) added afterwards scored 12/14 with two server findings on record
**Report:** [harness_report_v0.0.4.json](../harness_report_v0.0.4.json), [harness_report_v0.0.4_step2.json](../harness_report_v0.0.4_step2.json)

> Per-frame polling removed wherever a signal or timer could do the job; the test harness grew its fault-injection, fuzzing, fleet and soak tooling.

## Changes
### Client
- `NetworkManager` stub autoload removed from `project.godot`; `NetworkController` stops processing on web builds or when the UDP bind fails (it polled an unbound socket every frame).
- `global.gd`: `ws.poll()` stays as the one per-frame call; ping is a 1 s Timer carrying a timestamp (the frame counter gave 2.4 Hz at 144 fps and 0.5 Hz at 30 fps); reconnect is a one-shot 2 s Timer armed only from the closed state; the client reads `pong` and shows RTT in NetStats.
- Projectiles rely on `body_entered` only; the per-frame `get_overlapping_bodies()` scan is gone. `thorn.tscn` had no signal wiring at all, so the thorn now connects it in code.
- HUD icon textures are preloaded constants; `player_hit` dead code removed; the lobby uses the same signal table and `_exit_tree` disconnect as the arena.

### Harness, Step 2
- Per-bot latency / jitter / loss, `GodotClient` fleet runner, `fuzz`, `lag`, `slow_reader`, `stop_pinging`, `--soak` with RSS / thread / fd sampling, notes in the report.
- Findings recorded against this build: no frame length cap (64 MB header accepted, connection never closed), 512 KB payload relayed to everyone, no backpressure for a stalled reader (225 KB queued in 20 s).
