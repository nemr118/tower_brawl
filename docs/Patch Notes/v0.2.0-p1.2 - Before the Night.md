# v0.2.0-p1.2 - Before the Night

**Date:** 2026-10-10 · **Phase:** P1, before the first play night (the user's picks) · **Harness:** the P1 proofs on the PC (below); the relay harness does not apply to the new server
**Report:** the server's report lines, `bench_results/<date>/v2_server.jsonl`

> On the laptop since 2026-10-10 16:15, beside the old game. The night had not happened yet (the sheet was empty, and the laptop had no client since 14:37), so the user picked three fixes to go first. After FIGHT the bots now stand still 1 to 1.5 s: before, they shot within 0.1 s, and a person standing still died in the first second in 22 of 40 rounds. A match with fewer than 2 fighters left goes back to the lobby (backlog 35). A phone stuck on "Connecting" now says which page to open to accept the certificate.

## Changes
- **1. Bots wait at FIGHT** (`bench/sim/sim.gd`). `BOT_WAIT_MIN` 60 and `BOT_WAIT_MAX` 90 ticks. `start_round` gives every fighter a `wait_t` in that range, and only the brain reads it. While it counts down, `_brain` does nothing: no move, jump, drop, dodge or shot. People move from the first tick of FIGHT. The benchmark (`_init`, `_respawn`) never sets it. The first try held only the shot. Then the proof showed bots dropping onto the fighter below in 5 to 10 ticks, from spawn spots that sit right above another (Found, below), so the user picked "bots wait still".
- **2. A match stops below 2 fighters** (backlog 35, `bench/server/game_server.gd`). When a round ends and the next round would have fewer than 2 fighters (`_people() + _bots_now() < 2`), `_stop_match()` runs. It prints `[MATCH] stopped after N rounds: M fighter left (score)`, sends everyone a `note` ("The match stopped: a match needs 2 fighters."), and goes `_to_lobby()`. Nobody wins that match. A match that someone just won still ends the normal way, because that check comes first.
- **3. The `[KILL]` line says when.** Each line now ends with "N.NN s after FIGHT" (`_round_secs()`), so the laptop's journal shows how soon people die.
- **4. The certificate hint** (`bench/client/game_client.gd`, `lobby.gd`). After `STUCK_S` = 5 s with no connection to a `wss://` server, the lobby line says: "Still connecting. Open https://HOST:8091 in this browser once and accept the warning (an error page after that is fine), then come back here." While it shows, the controls help hides, so its 3 lines fit. It never shows with a wrong version.
- **5. The probe.** `bench/tools/input_probe.gd` has rule 24, "bots stand still and hold fire 1 to 1.5 s after FIGHT": 20 rounds of 1 still person + 7 bots.

## Found on the way (reported, not fixed)
- **Three spawn spots sit right above another one:** (300, 900) over (240, 1020), (1620, 900) over (1680, 1020), and (960, 420) over (960, 660). In 200 rounds with the shot held only, they gave 113 of the 142 stomps in the first second. Now the bots' wait covers the first second, but two people can still drop on each other there. TowerFall's levels keep spawn spots apart, and it has no spawn shield: its free-for-all shuffles the level's spots, and with 2 players the second one gets the spot opposite the first. For the super arena (G5): no spawn spot over another.
- **A note for the laptop's journal:** `ERROR: Missing or invalid header 'upgrade'` means someone opened `https://…:8091` as a page (the hint's step). It is not a fault.
- **Test tools:** `pkill -f` and `pgrep -f` with the server's arguments also match the shell that runs them, and it killed my own command twice: stop a test server by its PID. `$!` after `cd … && godot … &` is the subshell's PID, not Godot's: start `godot … &` on its own line. The headless server ignores SIGINT; SIGTERM stops it. The page needs about 20 s in headless Chromium before it has run 5 s (`v2_shot.py --wait 20` for the hint).
