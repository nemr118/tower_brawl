# v0.0.40 - LAN Server Kit

**Date:** 2026-09-07 · **Phase:** the laptop server for family nights: bots, deck controls, deploy and pull scripts, join / class / kill / leave records; the v0.1.0 release candidate · **Harness:** 24/24 with `--restart-each`, no Minor
**Report:** [harness_report_v0.0.40.json](../harness_report_v0.0.40.json) · the laptop: [[laptop-server]] · release: [[release-v0.1.0]]

> An old laptop now runs the game server for family nights, so the main PC is free to play ([[laptop-server]]). A side session set it up on 2026-09-07 and wrote the tools for it; this build folds that work into the project, adds what a seven-player free-play evening should record, and is the build deployed to the laptop for tonight. No game rule, packet or scene changed. The tools landed in the repo with the v0.0.39 commit by accident of `git add -A`; this page is where they are described.

## The laptop, in short
Headless Arch on an i7-3630QM with 8 GB, hostname `towerbrawl`, user `nemr`. The game lives in `~/tower_brawl` (server, certs, game source for headless bots, `tools/`, `build/web`), `towerbrawl.service` starts it at boot, Godot 4.7.2 is installed. The screen auto-logs in and shows a help box with the play link, then the deck with a SERVER panel. It takes DHCP, so the address changes per house; the MAC is `08:60:6e:09:b4:a7` (`ip neigh | grep -i 08:60:6e` from the PC). Passwords are still the temporary ones; the user changes them.

## Changes
- **`tools/tbbot.py`** (side session). `tbbot add [persona]`, `remove`, `clear`, `list`: real headless Godot clients with a bot brain, joining `ws://127.0.0.1:8081`, up to 4, pid and log files in `.bots/`. Backlog 19 (fill with bots) closes as a tool, not a server feature.
- **`tools/watch_server.py --controls`** (side session). A SERVER panel on top of the deck: the LAN play link, buttons for **+ bot**, **- bot**, **clear bots**, **wifi help**, keys `a`, `r`, `x`, `w`, Esc closes the wifi panel. Without the flag the deck is unchanged.
- **`tools/console.sh`, `tools/console_session.sh`** (side session). The help box and the loop the laptop screen runs (box, deck, shell, repeat).
- **`tools/deploy_laptop.sh <ip>`** (side session, one change here). Rsyncs the server, certs, game source, `tools/` and the current `build/web` files to the laptop and restarts the service. New: `TB_SUDO_PASS=...` in the environment skips the sudo prompt, for a script or an agent; without it `ssh -t` asks as before.
- **`tools/pull_laptop_logs.sh <ip>`** (new). Copies `client_stats.jsonl` (and `.1`), `server.log`, `status.json` and the bot logs into `playtest_logs/<date>_<ip>/` on the PC and lists the matches. `playtest_logs/` and `.bots/` are in `.gitignore`.
- **`serve_game.py`.** Five more record kinds in `client_stats.jsonl`, next to the cards and the match / round markers of v0.0.37: `join` (seat, name, link, address, bot persona, reclaim and rejoin flags), `name`, `lock` (seat, class), `kill` (killer, victim, both names, weapon, lives left, who saw it, round, self-kill flag) and `leave` (seat, why: pressed leave, grace expired, disconnected with the seat held). Thirteen `_stats_log` calls in all. Nothing is sent to a player.
- **`tools/stats_table.py`.** `--summary` prints a match as a story: one row per seat with name, class, kills, deaths, K/D, self-kills and weapons, the round winners, and the devices that were in it. `--events` prints every marker of a match or window in order. `--file` reads a pulled night.
- **Docs.** [[laptop-server]] gains "What the laptop records during a game night" and how to find the address. [[Commands]] has a laptop section. The release runbook deploys to the laptop after the tag and rolls it back the same way. The master sheet's section 0 names the laptop as the server for family nights. PASSDOWN: backlog 19 closed.
