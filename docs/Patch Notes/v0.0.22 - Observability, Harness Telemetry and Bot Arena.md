# v0.0.22 - Observability, Harness Telemetry and Bot Arena

**Date:** 2026-09-03 · **Phase:** before Phase 3c, the live operations deck · **Harness:** 18/18 (--restart-each)
**Report:** [harness_report_v0.0.22.json](../harness_report_v0.0.22.json)

> The terminal dashboard grew into a full deck: it shows the test harness while it runs, a kill timeline with round marks, kills and deaths per seat, each player's ping, a bot arena with room for future smart bots, and a tidier traffic view. The server counts kills and pings, the bots say who they are, and two small bugs are fixed on the way.

## Changes

**The harness tells the dashboard what it is doing** (`tools/chaos_bots.py`, `harness_state.json`)
- The problem: while the test harness ran, the dashboard only showed the server. You had to read the harness terminal to know which test was on.
- Now the harness writes a small file, `harness_state.json`, next to `status.json`. It writes it when a run starts, when a scenario starts, at every step it announces, at every finding, and when a scenario ends. A tiny helper thread refreshes a heartbeat once a second so the dashboard knows the run is still alive.
- The file holds: the run state (`running`, `restarting`, `done`, `aborted`), the list of scenarios with how many passed, failed or were Minor, the running scenario with its description, its last step, how long it has played and how long it will play, its findings and warnings, and the bot cards of the headless Godot clients in a fleet run.
- The long scenarios (`fleet`, `lag`, `play`) used to sleep the whole time. Now they sleep in 5-second naps and read the tail of each Godot log in between, so the bot cards reach the dashboard while the fleet still plays. Nothing they check changed.
- When `--restart-each` restarts the server, the file says `restarting`, so the dashboard shows a yellow "server restarting" bar instead of the red "server down" one.
- It is written under a temp name and renamed, so a reader never sees half a file. `--no-state` turns it off. The file is in `.gitignore`.

**A Minor mark between PASS and FAIL** (`tools/chaos_bots.py`)
- The problem: a scenario could pass while the server still wrote a traceback in its log. Nobody saw it.
- Now the harness has `ctx.warn(name, detail)`: a soft finding. The scenario still passes, but the report marks it `MINOR` and lists the warning. Two sources so far: `server.error-logged` (the server wrote an `ERROR` line or a traceback during the scenario) and `fleet.script-warning` / `scenario.lag.script-warning` (a Godot client printed a `WARNING:` line).
- The report table has a new `warn` column, a `WARNINGS` block, and the last line says `18/18 scenarios passed   MINOR: fuzz` when that happens. The JSON report carries `warnings` and `minor` per scenario.

**The server counts the fight** (`serve_game.py`, `status.json`)
- The problem: the dashboard could show who is alive, but not who is winning.
- Now the server counts kills and deaths per seat for the current match, and keeps a timeline: every kill as `[seconds since the match started, killer, victim, weapon, round]` and every round as `[number, start seconds, winner]`. Everything starts from zero when a new match starts and stays readable after the match ends, until the next one.
- `status.json` grew: each seat has `kills`, `deaths`, `rtt_ms` and `bot`; the match has `timeline`; the top level has `bots` (how many seated players are bots).
- The `[STATS]` line now says `players=4 (2 bots)` when bots sit in the match. That was item 5 on the "later" list.

**Every player sends its ping** (`scripts/global.gd`, `serve_game.py`)
- The problem: only the client knew its own round trip time (from the `pong` answer). The server, and so the dashboard, had no ping per player.
- Now every `ping` packet carries `rtt`, the round trip the client measured last time. The server keeps it per connection and the dashboard shows it in the `Ping` column. One extra number in a packet that already went once a second.

**Bots say who they are** (`scripts/global.gd`, `scripts/bot_brain.gd`, `tools/chaos_bots.py`, `serve_game.py`)
- The problem: the server could not tell a bot from a person, so the dashboard could not either.
- Now a headless client with `--ai=<persona>` puts `"bot": "<persona>"` in its `request_join`, and a harness bot puts `"bot": "protocol"`. The seat gets a 🤖 badge on the dashboard right away.
- A bot brain also sends a `bot_status` packet every 5 seconds, next to the `🧠 [Bot …]` line it already printed: persona, seed, difficulty, uptime, its action counts (decisions, moves, jumps, dashes, attacks, specials, evades), its wrap numbers, its aim error, and empty slots for the future: `state` (like seeking, retreating, camping), `target`, `goal`, `combat` (accuracy, air time, damage) and `learning` (episode, reward, weights, deltas). The griefer already fills `state` with its mood, and every brain fills `goal` with where it is steering.
- The server keeps the last card per seat in `status.json` and never sends it on to the players. A card bigger than 1 KB is dropped. The card goes away when the seat is freed.

**The dashboard is a deck now** (`tools/watch_server.py`)
- The picture is a stack of panels. A panel with nothing to show is not drawn, so a quiet server looks like before.
- `HARNESS` shows while a run is alive: the scenario name, its place in the suite, a progress bar (it also moves inside a timed scenario), the run time, what the scenario tests, the last step, a checklist with ✔ PASS, ✖ FAIL, ▲ Minor, ● running and ○ waiting, and the findings and warnings of the running scenario. A finished run stays as one summary line for ten minutes.
- `SEATS` has new columns: `K/D` (kills, deaths and the ratio), `Ping`, and `Health`: `good`, `laggy` (over 150 ms), `slow` (the send queue is backing up), `quiet` (nothing heard for 3 s), `stalled` (5 s), `held` or `empty`. A bot seat shows 🤖 next to its name.
- `FIGHT` shows once the match has a kill: a `kills/5s` bar chart in block letters, one lane per fighter with ◆ for a kill, ✕ for a death and ◈ for both in the same 5 seconds, a ┃ line where a new round started, and a `round` row with `R1`, `R2`, … under the lanes. The newest 5 seconds sit on the right; older columns scroll off the left. It stays after the match ends, marked "(last match)", until the next match starts.
- `BOT ARENA` shows when a bot brain is in the match (or a fleet run reports one): seat, persona, difficulty, state, target, accuracy, air time, decisions, attacks, specials, evades, wraps, longest fall loop, aim error, uptime and the learning deltas as small chips. Empty slots print `-`. The server's card and the harness's card for the same seat are merged, the bot's own card wins.
- `TRAFFIC` is two lines now: IN with the top packet kinds per second, OUT with fails, drops, queued frames and threads.
- `EVENTS` takes the rest of the screen, so the newest lines are always visible. `--plain` prints the same sections as text, `--once` prints one picture, `--harness-file` points at another state file.

**Two small fixes** (`serve_game.py`)
- "1 lives left" is now "1 life left" (`_lives_text`).
- The fuzz scenario sends `"victim": "abc"` in a `player_died` packet. `int("abc")` blew up and left a traceback in `server.log` on every run. A new helper, `_as_int`, reads whole numbers from packets and gives a default for anything else, so the bad packet is dropped quietly. Killer and the new `rtt` field use it too. The new Minor check would have caught this.

**Checked**
- Full suite with `--restart-each`, the dashboard running next to it: all 18 pass, no Minor. No traceback in `server.log` after `fuzz`.
- A fleet run with four brains (`--scenario fleet --godot 4 --ai chaser,sniper,turtle,griefer --duration 60`): the bot arena shows all four cards from the server (persona, difficulty, actions, aim, the griefer's mood), the seats show 🤖, the fight timeline draws kills and a round line.

## Metrics
| Measure | before | after |
|---|---|---|
| Dashboard panels | header, seats, traffic, events | + harness deck, fight timeline, bot arena; panels fold when empty |
| Harness visibility | its own terminal only | `harness_state.json` once a second, PASS / FAIL / Minor checklist |
| Result levels | PASS, FAIL | PASS, MINOR, FAIL |
| Per-seat numbers | lives, crowns, packets | + kills, deaths, K/D, ping, health |
| Bot detection | none | `"bot"` in `request_join`, `bot_status` every 5 s, `(N bots)` in `[STATS]` |
| `ping` packet | `{type, t}` | `{type, t, rtt}` (one number more, once a second) |
| Fuzz run traceback in `server.log` | one per run | none |
| Server dependencies | standard library | standard library (unchanged) |
