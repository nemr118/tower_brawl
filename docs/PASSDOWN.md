## Phase 3b step 5: human playtest checklist (phone + PC)
Open `https://192.168.4.21:8443/play` on both (hard reload if the console prints VERSION MISMATCH). Fill two seats with bots if needed: `godot --headless --path . -- --autojoin --ai=chaser --name=Bot1` and `--ai=sniper --name=Bot2`.
1. **Smoothness at rest and in motion.** Watch the other human's fighter walk, reverse, jump and dash: no visible stutter, no rubber-banding, no "catching up" bursts. Compare with the v0.0.8 memory of the lerp (puppets used to ease toward every sample).
2. **Delay.** The puppet is drawn 100 ms behind the sender by design. Stand next to each other and jump at the same time: the other's jump should start about a tenth of a second late, constantly, never variably.
3. **Seams.** Walk through the left/right seam and drop through the bottom: the other screen must show a clean step across, never a glide across the arena. Do it while dashing too.
4. **Teleports.** Mage blink (special) and respawns must appear as an instant step on the other screen, not a 50 ms slide. Druid egg and bear toggles must change on the drawn body, not early.
5. **Hits line up.** Melee (knight sword, bear slash, rogue dash-slash) and stomps on a moving target: do they register where the target is drawn? Shield and dash invulnerability: hitting a puppet mid-dash must not kill it; a shielded knight must block.
6. **Idle then move.** Stand still for 3 s, then sprint: the puppet must start moving within ~150 ms, not hold and then snap.
7. **Phone in a bad spot.** Move the phone away from the router until `rtt` in the browser console NetStats line climbs above ~150 ms, then repeat 1–3: the puppet may extrapolate (straight-line continuation for up to 200 ms then freeze) but must never glide across a seam or jump around when packets catch up. Note `jitter=` and `extrap=` from that phone's NetStats line.
8. **Rejoin.** Reload the phone mid-round: the others' puppets must resume clean (the ring is cleared on rejoin), and your own fighter must not jitter on the PC after you return.
9. **Console.** Zero errors on both browsers; the NetStats line every 5 s with `puppets=` populated.
Record findings in `docs/Playtest v0.0.15.md` (copy the shape of [[Playtest v0.0.8]]); fixes ship as v0.0.16+; then Phase 3c (5-second history ring, kill-frame stamping, server-sent round-end duration).

## How to work here
- **Rules:** `CLAUDE.md` in the repo root (no `.tscn` edits; every GDScript change ships via `./bump_build.sh --title "..."`, which compile-checks with autoloads live, bumps `v0.0.x`, exports, cache-busts the pck, generates the patch-notes page; patch notes on every bump). The user approves one phase at a time; report bugs found outside the phase, don't fix them unasked.
- **Verify:** `godot --headless --path . --script tools/check_scripts.gd -- --no-net` (`--check-only` is useless here) then `./venv/bin/python tools/chaos_bots.py --restart-each --json docs/harness_report_<ver>.json`. `--scenario X` for one; `--list` for all 17; `--soak 30` for leaks; `--scenario play --latency-ms 120 --loss 0.05` for fault injection.
- **Serve/play:** `systemctl --user restart towerbrawl` after any `serve_game.py` change (client-only changes need no restart: the server re-reads the version from `global.gd`). Everyone opens `https://192.168.4.21:8443/play` (redirects to the current build; PC on plain http is not a secure context in Chromium). Logs: `server.log` (never rotated, contains days of history: filter by the last "Game version" banner line), `.harness_logs/godot*.log`.
- **Headless real client:** `godot --headless --path . -- --autojoin --name=X --class=N` (NetStats line every 5 s in its stdout). Add `--ai=<persona> [--ai-seed=N] [--ai-difficulty=0..1] [--latency-ms=N]` for a bot brain (`🧠 [Bot …]` status line every 5 s with action counts, wrap stats and the aim self-check; the persona picks its class unless `--class` is given). Harness: `--scenario fleet --godot 4 --ai chaser,sniper,turtle,griefer` (comma list = one persona per client, no protocol bots at 4), `--godot 2 --ai sniper,rusher` (2 brains + 2 protocol bots), `--ai-difficulty 0.3`, `--latency-ms 120` also reaches the Godot clients. Bot logs land in `.harness_logs/godot<N>.log`.
- **Docs live in `docs/`** (= the vault). Commands and gotchas: [[obsidian_notes]].

## Architecture in one screen
- `serve_game.py`: authoritative lobby/match state (slots, playing/waiting, alive, stocks, scores, rounds, 5-crown match end), relay for everything else. One reader thread per socket + one `ClientConn` writer thread with a bounded queue (movement dropped first when backed up; stalled peers dropped after ~5 s of a non-shrinking kernel backlog). TCP keepalive instead of app-level timeouts (hidden tabs keep their seat). Frame cap 4 KB, relay cap 1 KB. Sender stamped server-side. Client token gates slot reclaim; 8 s rejoin grace mid-match; 1.5 s forfeit grace on explicit leave; observer-authoritative deaths deduped per 1.5 s.
- `scripts/global.gd`: the only network code on the client. JSON for events, **binary for movement**: `sync_pos` 11 B `[type, sender, tick u16 (20 Hz slot clock), x*10 s16, y*10 s16, aim 0.1° u16, flags]`, `spawn_projectile` 9 B. Layout mirrored in `serve_game.py BIN_TYPES` and `tools/chaos_bots.py`. Signals out to `arena.gd` / `character_select.gd` (both connect from a table and disconnect in `_exit_tree`). Auto-rejoin after a reconnect, scene correction to the server state, combat state (ammo, tick) persisted for reloads.
- `scripts/player.gd`: local sim + 20 Hz send with idle suppression on a slot-clock tick; remote puppets render from a 16-sample snapshot ring 100 ms behind the sender (`_render_snapshots`: seam-unwrapped, flags at render time, ≤ 200 ms extrapolation past the newest sample, 80 px teleport snap; Phase 3b); per-frame puppet-jitter telemetry into `Global.puppet_sample`; deaths reported by whoever saw the hit.
- `scripts/bot_brain.gd`: AI opponent attached by `arena.gd` to the local fighter under `--ai=<persona>`. Perceives from the scene tree, acts with `Input.action_press/release` (runs before the fighter in the same physics frame via `process_physics_priority = -10`), aims with a synthetic `InputEventMouseMotion` (verified: 0.0° error). 10 Hz decisions through a reaction-delay queue, gaussian aim error, seeded RNG. Navigation: wrap-aware steering, rises beyond one jump use a jump + upward dash at the apex or a drop through the bottom seam, and an airborne bot over an empty column air-steers to its landing platform (`_landing_move`). Shared: inbound-projectile threat test, lead-shot solver, evade by dash. Personas: `wanderer`, `chaser` (knight), `sniper` (mage), `turtle` (knight), `rusher` (rogue), `griefer` (druid: seam drops and hops, powerup camping, dashes into projectiles, shield spam, bear toggles).
- `tools/chaos_bots.py`: protocol oracle + 17 scenarios + fuzz + fault injection + soak + `GodotClient` fleet runner (parses the `🧠 [Bot` line: `fleet.bot-idle`, `fleet.bot-fall-loop`, `fleet.bot-missing`, `fleet.no-kills`, `fleet.no-round-end` at 150 s+; parses `puppets=`: `puppet_gate` → `fleet.puppet-jitter` / `fleet.puppet-snaps`, also on the `lag` scenario's Godot observer).

## Open backlog / edge cases
1. **Ranger reload mid-match** loses the stuck arrows on the ground (projectiles are not in any snapshot) → 0 ammo, no pickups until the next round. Simple fallback: restore ≥1 arrow on a mid-match rejoin; proper fix with the class-kit revisit (arrows in the join snapshot, or slow regen). See [[Playtest v0.0.8]].
2. ~~`p0_left` InputMap error~~ **fixed in v0.0.11**: the three P1-bind copies in `global.gd` now require `my_player_id >= 2` (id 0 = spectator). Was the intermittent red on the default fleet scenario.
3. Spectating from a second tab of the same browser shares Chromium's renderer main thread with the game tab (input stalls during heavy work in the other tab). Mitigated (inputs released on focus loss); use a second device/profile to spectate.
4. `server.log` / `debug.log` never rotate (untracked; multi-day files). Consider rotation.
5. Godot client `player_configs` still carries a default class per slot; harmless.
6. **Ranger arrow economy:** three arrows per life and pickups only from own stuck arrows; a bot (or a player) that fires off-screen is disarmed for the round. The sniper persona plays mage for this reason. Same root as item 1 (class-kit revisit: arrows in the join snapshot or slow regen).
7. ~~No screen wrap while shielding or in egg form~~ **fixed in v0.0.11** (`_check_screen_wrap()` in both early-return branches of `player.gd`). Found by the griefer persona.
8. ~~Turtle can chain 4 bottom wraps~~ **fixed in v0.0.13** (no air shield over an empty column, as the griefer).
9. **Arena voids are a mechanic, not a bug** (user decision, v0.0.11): the columns beside the seam (x < 55, x > 585) and the bottom seam are the way to high ground. Bots plan routes through them (`bot_brain.gd` `_steer_to`, `_landing_move`); humans can still fall-loop for a while.
